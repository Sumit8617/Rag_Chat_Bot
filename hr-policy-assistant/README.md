# HR Policy Assistant

A grounded Retrieval-Augmented Generation (RAG) service that answers
employee questions from uploaded HR policy documents only — with
citations, and a reliable refusal when the policies don't cover the
question.

## What this is (and isn't)

- **LLM: API-based.** Answers are generated by Google's Gemini API
  (`gemini-3.6-flash` by default), using the free tier. No LLM runs
  locally.
- **Embeddings: local and free.** Semantic search uses
  `sentence-transformers` (`all-MiniLM-L6-v2`) running entirely on your
  machine — no embedding API calls, no per-query cost, and none of your
  policy text leaves your machine at the embedding step.
- **Vector store:** ChromaDB, file-backed (`./chroma_db`), zero external
  services to run.
- **Retrieval:** hybrid — vector similarity **and** exact keyword/section
  matching, fused with Reciprocal Rank Fusion (RRF). This matters for HR
  policies specifically, because employees often ask about exact clause
  numbers ("what does section 4.1 say?"), which pure vector search
  handles poorly.

See [DESIGN.md](./DESIGN.md) for the full architecture and the
reasoning behind these choices.

## Quick start (under 10 minutes)

### 1. Prerequisites

- Python 3.10+
- A free Gemini API key from [Google AI Studio](https://aistudio.google.com/apikey)
  (no credit card required)
- Internet access for two one-time downloads: Python packages, and the
  embedding model (Step 3 below)

### 2. Install

```bash
git clone <your-repo-url>
cd hr-policy-assistant
python -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

`requirements.txt` pins exact versions that have been verified working
together (FastAPI, ChromaDB, sentence-transformers, google-genai,
Streamlit). A `.gitignore` excludes `.env`, `chroma_db/`, `venv/`, and
`__pycache__/` — never commit real API keys or the local vector index.

### 3. One-time setup: download the embedding model

The embedding service is configured with `local_files_only=True` (see
[DESIGN.md — Trade-offs](./DESIGN.md#5-trade-offs) for why). This means
it will **not** silently reach out to the internet on every run — it
expects the model to already be cached locally. Download it once:

```bash
python -c "from sentence_transformers import SentenceTransformer; SentenceTransformer('all-MiniLM-L6-v2')"
```

This caches the model under `~/.cache/huggingface/` (a few hundred MB,
one-time only). After this, the app works fully offline for embeddings.

### 4. Configure environment variables

```bash
cp .env.example .env
```

Edit `.env` and set your key:

```
GEMINI_API_KEY=your-real-key-here
```

Leave the other values as-is unless you have a reason to change them —
see [.env.example](./.env.example) for what each one does.

### 5. Index the sample policies

Three sample policies ship in `data/policies/`. Index them:

```bash
PYTHONPATH=. python -c "
from app.ingestion.loader import load_document
from app.ingestion.chunker import chunk_document
from app.ingestion.indexer import PolicyIndexer

indexer = PolicyIndexer()
for fname in ['leave-policy.md', 'benefits-policy.md', 'it-security-policy.md']:
    text = load_document(f'data/policies/{fname}')
    chunks = chunk_document(text=text, document_name=fname)
    count = indexer.index_chunks(chunks)
    print(fname, '->', count, 'chunks indexed')
"
```

Expected output (chunk counts will match the current sample docs):

```
leave-policy.md -> 12 chunks indexed
benefits-policy.md -> 7 chunks indexed
it-security-policy.md -> 8 chunks indexed
```

### 6. Run the API

```bash
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Check it's alive (this works even if `GEMINI_API_KEY` isn't set yet —
`/health` doesn't depend on it):

```bash
curl http://127.0.0.1:8000/health
# {"status":"ok"}
```

### 7. (Optional but recommended for demos) Run the chat + admin UI

In a second terminal, with the same virtualenv active:

```bash
streamlit run streamlit_app.py
```

Open the URL Streamlit prints (typically `http://localhost:8501`). This
gives you:

- The employee-facing chat (main panel)
- An **admin upload widget** in the sidebar ("📤 Admin: Upload a
  policy") — pick a `.md`/`.txt` file, click "Index this document,"
  and it's immediately searchable in the chat below. This is the
  fastest way to demo requirement 8 ("works with a new policy uploaded
  during review") without leaving the browser.

## Trying the three required scenarios

All three of the following have been run live against a real Gemini
API call and a real local embedding model (not just unit-tested in
isolation) — see the exact responses below each command.

**Direct factual question:**

```bash
curl -X POST http://127.0.0.1:8000/ask \
  -H "Content-Type: application/json" \
  -d '{"question": "How many casual leave days can I carry forward?"}'
```

Verified live response:

```json
{
  "answer": "A maximum of 8 days of unused casual leave may be carried forward to the next calendar year.",
  "citations": [
    {"document": "leave-policy.md", "section": "4.1 Casual leave carry-forward"}
  ]
}
```

**Table / structured policy question:**

```bash
curl -X POST http://127.0.0.1:8000/ask \
  -H "Content-Type: application/json" \
  -d '{"question": "Does the Standard health tier cover dental implants?"}'
```

Verified live response:

```json
{
  "answer": "No, dental implants are not covered under the Standard health tier.",
  "citations": [
    {"document": "benefits-policy.md", "section": "2. Health coverage tiers"}
  ]
}
```

**Unknown / off-policy question:**

```bash
curl -X POST http://127.0.0.1:8000/ask \
  -H "Content-Type: application/json" \
  -d '{"question": "What is the company'\''s maternity leave policy?"}'
```

Note: the sample policies deliberately don't cover maternity leave.
"Can I expense a personal home gym?" is *not* a good off-policy example
here, even though the assignment brief uses it — `benefits-policy.md`
Section 4 ("Wellness") explicitly states gym equipment isn't
reimbursable, so the system correctly *answers* that question with a
citation rather than refusing (also verified live — see
`tests/evaluation_questions.json`, where it's correctly labelled
`answerable: true`).

Verified live response for the maternity-leave question (no invented
policy):

```json
{
  "answer": "I don't have enough information in the uploaded policies to answer this question. Please contact HR.",
  "citations": []
}
```

All three can also be tried directly in the Streamlit chat UI (Step 7)
instead of via `curl` — same underlying service, same results.

**Uploading a new policy (admin flow):**

Via the API:

```bash
curl -X POST http://127.0.0.1:8000/documents \
  -F "file=@path/to/new-policy.md"
```

Or via the UI: sidebar → "📤 Admin: Upload a policy" → choose file →
"Index this document."

Response: `{"document": "new-policy.md", "chunks_indexed": N}`. The new
policy is immediately searchable — no restart, no code change.
Re-uploading a file with the same name replaces its old chunks rather
than duplicating them.

## Environment variables

| Variable | Default | Meaning |
|---|---|---|
| `GEMINI_API_KEY` | *(empty)* | Required for `/ask` to work. Get one free at [Google AI Studio](https://aistudio.google.com/apikey). |
| `GEMINI_MODEL` | `gemini-3.6-flash` | Current (mid-2026), free-tier-eligible Gemini model. Free tier is rate-limited (roughly 5 requests/min, ~20–250 requests/day depending on Google's current limits) — fine for a demo, not for load testing. |
| `EMBEDDING_MODEL` | `all-MiniLM-L6-v2` | Local sentence-transformers model. Must be pre-downloaded — see Step 3. |
| `CHROMA_PATH` | `./chroma_db` | Where the vector index is persisted on disk. |
| `TOP_K` | `5` | How many chunks are returned to the LLM after hybrid retrieval. |

```bash
PYTHONPATH=. python tests/test_citation_validator.py
PYTHONPATH=. python -m json.tool tests/evaluation_questions.json > /dev/null && \
```

`test_evaluation.py` requires the sample policies to be indexed first
(Step 5) and a working embedding model; it does not require a Gemini
key (it only exercises retrieval + grounding, not generation).

## Known limitations

See [DESIGN.md — Trade-offs](./DESIGN.md#5-trade-offs) and
[DESIGN.md — If I had two more weeks](./DESIGN.md#6-if-i-had-two-more-weeks)
for a full discussion. Briefly:

- PDF upload isn't supported (`.md`/`.txt` only) — deliberate scope cut.
- Ingestion is synchronous; a very large upload blocks the request.
- No authentication on `/documents` (anyone can upload) — acceptable for
  this assignment's scope, called out explicitly as future work.
- Citation validation confirms a citation points to a real retrieved
  `(document, section)` pair; it does not independently verify the
  specific claim text is entailed by that chunk.
